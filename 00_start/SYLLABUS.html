Purpose

This course teaches engineers to make defensible forecasting and sequential- decision claims. Algorithmic sophistication is subordinate to a valid data or environment contract, a serious baseline, fair repeated evaluation, reproducible artifacts, and an honest limitation.

Every performance claim must identify the data or environment version, evaluation protocol, baseline, metric, repeated evidence, reproducible code and configuration, and at least one known limitation.

Learning outcomes

After the common Core route, every student can:

  1. define a time-series target, unit, frequency, origin, horizon, and prediction-time feature boundary;
  2. detect temporal leakage and test date/index assumptions;
  3. implement and defend mean, last-value, and seasonal-naive baselines;
  4. compare seasonal naive, ETS, and bounded SARIMA on identical rolling origins;
  5. interpret residual diagnostics, uncertainty, operational loss, and limits;
  6. specify an inventory MDP, reward decomposition, horizon, and truncation semantics;
  7. implement transparent random and reorder comparator policies;
  8. trace and implement tabular Q-learning without an opaque training framework;
  9. compare frozen policies over common evaluation seeds using cost, service, resource, and safety metrics;
  10. reproduce a result from versioned data/environment, configuration, code, seeds, and evidence paths;
  11. write a bounded operational recommendation and state what would reverse it.

Support, Core, and Extension

All students are assessed against the same Core outcomes.

  • Support provides guided cells, checkpoints, micro-examples, visual explanations, and recovery instructions.
  • Core is the common assessed protocol and can earn the maximum mark.
  • Extension adds one bounded ablation, sensitivity, uncertainty, or engineering study only after Core validity passes.

An extension never repairs leakage, protected-data tuning, a missing baseline, unequal cases/budgets, seed cherry-picking, or an irreproducible result. The ungraded diagnostic routes each student to only the bridge material they need.

Capstone

The capstone contains exactly:

  1. a forecasting release claim produced from TDo1;
  2. an RL policy release claim produced from TDo2;
  3. a cross-strand forecast-to-inventory operational and safety synthesis.

Development evidence from TD1–TD4 supports provenance and method explanation, but it is not substituted for either controlled release receipt. The capstone requires replayable artifacts, submission.yaml, claims_evidence.csv, an AI use log, contribution records, limitations, fallback, monitoring, and rollback.

Integrity and safety

Generative AI is allowed only when its tool, purpose, reused content, tests, and human verification are disclosed. A result that a student cannot explain or reproduce receives no credit. Pair work does not remove individual accountability.

The inventory policy remains a simulated classroom decision. It is not authorised for production, autonomous procurement, or real operational control.
