Accessibility and Inclusive Use

This package provides several ways to access the same content and evidence standard. It does not replace an official ESILV accommodation decision.

Available course formats

  • Each Badr lecture folder contains a searchable PDF, an English Markdown slide manuscript, formal references, and a VISUAL_ACCESSIBILITY.md description of the main diagrams.
  • Every practical topic has a Support starter with shorter steps, explicit checkpoints, and topic-specific hints, plus a Core starter with less scaffolding. Assessed-algorithm Support notebooks also include small visual examples where they clarify the loop or objective. Both routes have the same Core mark ceiling.
  • Lab README.md, rubric.md, and failure_modes.md files expose the task, success criteria, and recovery path as text rather than relying on spoken instructions alone.
  • The bridge lessons are ungraded, timeboxed, and include collapsible recovery answers.

Reading and navigation

  • Use the Markdown lecture manuscript when PDF reading order, magnification, or a screen reader makes the slide layout difficult.
  • Use the matching visual-accessibility file for a text explanation of diagrams and visual encodings.
  • Notebook headings follow the execution order. Navigate by headings, then run code cells top to bottom from a clean kernel.
  • Browser/editor zoom, font size, high-contrast themes, and keyboard shortcuts may be adjusted without changing the scientific protocol.

Accessible evidence you produce

Figures and tables submitted for assessment must remain understandable without colour alone:

  • label axes, units, methods, and evaluation populations;
  • combine colour with markers, line styles, direct labels, or patterns;
  • use readable contrast and avoid dense legends or tiny text;
  • add a one- or two-sentence caption stating the comparison and limitation;
  • provide the underlying CSV/JSON/table whenever a plot supports a numerical claim;
  • do not use screenshots as the only evidence for code, metrics, or errors.

Name files and headings descriptively. Keep notebook output compact so a reader does not have to traverse hundreds of log lines to find the result.

Support and accommodation boundary

Use the official ESILV channel for disability, health, timing, attendance, or assessment-format accommodations. Contact the teaching team early enough to prepare an approved format. The draft course package cannot itself authorize extra time, a changed individual-verification format, or an alternative deadline.

A technical help request should contain environment and error evidence only. Do not include a diagnosis, medical document, or other sensitive personal information in HELP_REQUEST.md, a notebook, Git history, or the pair repository.

If an approved accommodation requires a format not present in the package, report the exact access barrier and required format through the designated private channel. Do not wait until a timed session to disclose that the current artifact is unusable.

Accessibility self-check before submission

  • [ ] headings and execution order are clear;
  • [ ] plots do not rely on colour alone;
  • [ ] axes, units, legends, and captions are readable;
  • [ ] numerical claim evidence also exists as text or a table;
  • [ ] no decisive information appears only in an image or screenshot;
  • [ ] PDF figures used in the release brief have a nearby text explanation;
  • [ ] no sensitive accommodation information is present in submitted files.
